# Нагрузочное Тестирование С Locust

В проект добавлен сценарий в `locustfile.py`.

Файл описывает базовый набор нагрузочных действий:

- как устроен `Locust`
- как запускать виртуальных пользователей
- как нагружать чтение и запись отдельно
- как читать результаты прогона

## Что Сейчас Делает Сценарий

- логинится под учёткой из `.env`
- создаёт одного сотрудника на каждого виртуального пользователя в `on_start`
- отправляет запросы на `dashboard`
- читает данные сотрудника
- читает список клиентов сотрудника
- запускает короткий CRUD-сценарий: клиент -> счёт -> блокировка -> очистка

## Установка

Перед установкой можно проверить интерпретатор:

```bash
venv\Scripts\python.exe --version
```

Ожидаемая версия:

```text
Python 3.12.10
```

Если основное окружение уже установлено, добавь только `Locust`:

```bash
venv\Scripts\python.exe -m pip install -r requirements-load.txt
```

Если поднимаешь всё с нуля:

```bash
venv\Scripts\python.exe -m pip install -r requirements.txt
venv\Scripts\python.exe -m pip install -r requirements-load.txt
```

## Запуск Через Веб-Интерфейс

```bash
locust -f locustfile.py
```

После запуска открой:

```text
http://localhost:8089
```

Для первого прогона рекомендую:

- `Users`: `3`
- `Spawn rate`: `1`
- `Host`: оставить пустым, он берётся из `API_URL`

## Запуск Без UI

```bash
locust -f locustfile.py --headless -u 5 -r 1 -t 1m
```

Где:

- `-u 5` означает 5 виртуальных пользователей
- `-r 1` означает, что Locust будет добавлять по 1 пользователю в секунду
- `-t 1m` означает длительность прогона 1 минута

## На Что Смотреть В Результатах

- `RPS` показывает, сколько запросов в секунду прошло через систему
- `Avg` показывает среднее время ответа
- `P95` помогает увидеть, как ведут себя "медленные" 5% запросов
- `Failures` показывает, начала ли система ошибаться под нагрузкой

## Как Работать Сценарием Постепенно

1. Сначала запусти 1 пользователя и убедись, что сценарий вообще работает.
2. Потом запусти 3 пользователей и посмотри, какие ручки самые медленные.
3. После этого сравни, что быстрее: простое чтение или цепочка с созданием данных.
4. Затем увеличивай нагрузку постепенно: 5, потом 10 пользователей.


## Важное Замечание

Этот сценарий создаёт и удаляет реальные тестовые данные.

Поэтому для первых прогонов лучше:

- начинать с маленькой нагрузки
- не запускать сразу большие значения users
- смотреть, что очистка действительно сработала
